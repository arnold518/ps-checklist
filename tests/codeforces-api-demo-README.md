# Codeforces API Demo - Interactive Table

This demo fetches contest data from the Codeforces API and displays it with **exactly the same behavior** as the PS-Checklist's practice records table, including interactive info panels.

## Features

### Core Functionality
- **URL Parsing**: Automatically extracts contest ID from Codeforces URLs
- **API Integration**: Uses Codeforces public API to fetch contest information
- **Identical Table Format**: Displays problems in the exact same table style as the main application
- **Support for Both Contest Types**:
  - Regular contests: `https://codeforces.com/contest/1234`
  - Gym contests: `https://codeforces.com/gym/102156`

### Interactive Features (Copied from Practice Records)

#### Contest Info Panel (Blue Border)
Click the contest ID cell to show:
- Contest name and ID
- Problem count
- Links to:
  - 📊 Standings
  - 📝 Problems page
  - 🔗 Codeforces contest page

#### Problem Info Panel (Green Border)
Click any problem cell to show:
- Problem name and ID
- **Status selector**: Click to cycle through:
  - Not Attempted (gray)
  - Attempted (orange)
  - Solved (green)
  - Reviewed (light green)
- **Difficulty selector**: Use +/- buttons to adjust difficulty level (0-5)
- **Codeforces link**: Opens problem on Codeforces

### Data Persistence
- All status and difficulty data is saved to **localStorage**
- Data persists across page reloads
- Each problem is tracked by `{contestId} >> {problemIdx}`

## Usage

1. Open `codeforces-api-demo.html` in a web browser
2. Enter a Codeforces contest URL (or use one of the examples)
3. Click "Fetch Contest Data"
4. The table will display with all problems from the contest

## API Endpoint Used

```
https://codeforces.com/api/contest.standings?contestId={id}&from=1&count=1&locale=en
```

This endpoint returns:
- Contest metadata (ID, name, type)
- Full problem list (index, name, points)

**Note**: The `locale=en` parameter ensures all problem names are returned in English, not Russian.

## CORS Considerations

### API Calls (✅ Works)
The Codeforces API supports CORS, so fetching contest data works directly in the browser.

### HTML Scraping (⚠️ Blocked by CORS)
Fetching announcement and editorial links requires parsing the contest HTML page, which is **blocked by CORS** in browsers.

**Current implementation:**
- ✅ **Statements link**: Generated by adding `/problems` suffix
- ✅ **Standings link**: Generated by adding `/standings` suffix
- ✅ **Codeforces link**: Direct contest URL
- ❌ **Announcement link**: Requires HTML scraping (CORS blocked)
- ❌ **Editorial link**: Requires HTML scraping (CORS blocked)

**Solutions for production:**

1. **CORS Proxy** (Recommended for demo)
   ```javascript
   const proxyUrl = 'https://your-cors-proxy.com/';
   const response = await fetch(proxyUrl + contestUrl);
   ```

2. **Backend Server**
   - Create a Node.js/Python server that fetches and parses the HTML
   - Return announcement/editorial links as JSON

3. **Codeforces API Blog Search** (Alternative approach)
   - Use `blog.entry` API with contest ID in query
   - Search for blog entries tagged with contest ID
   - This is more complex but avoids HTML parsing

4. **Browser Extension** (Development only)
   - Install a CORS bypass extension
   - Only for local testing, not for production
